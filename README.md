# Генератор Договоров (Contract Generator)

Консольная и Telegram-система для автоматической генерации договоров в форматах DOCX и PDF на основе шаблонов из Google Drive.

---

## Принципы Проекта

1. **Разделение ответственности**: Один модуль выполняет одну задачу.
2. **Чистый интерфейс**: Консольный и Telegram интерфейсы не содержат бизнес-логики.
3. **Простой рендеринг**: Шаблонизатор (Renderer) занимается исключительно заменой плейсхолдеров и не вычисляет данные.
4. **Вычисляемые поля**: Все динамические или форматированные поля формируются строго процессорами (Processors).
5. **Масштабируемость**: Добавление нового вычисляемого поля требует создания нового процессора, а не изменения существующих.
6. **Управление контентом**: Добавление проектов, вакансий или шаблонов осуществляется простым изменением структуры папок в Google Drive.
7. **Очистка данных**: Временные файлы автоматически удаляются после отправки готового PDF-файла.
8. **Внешняя конфигурация**: Все настройки хранятся вне кода — в `.env` и файлах конфигурации `config/*.yaml`.
9. **Единая точка входа**: `ContractEngine` — единственный интерфейс для взаимодействия с бизнес-логикой.

---

## Схема Потока Данных (Data Flow)

```text
Консоль / Telegram
-> ContractEngine (Единый движок)
-> Google Drive + Локальный кэш
-> EmployeeParser (Парсер текста сотрудника)
-> ProcessorRegistry (Реестр процессоров данных)
-> DOCX Renderer (Рендеринг шаблона DOCX)
-> PDF Converter (Конвертация в PDF)
-> Отправка PDF / DOCX пользователю
-> Очистка папки tmp
```

## Структура Каталога Google Drive

Каталог Google Drive является первоисточником для структуры проектов, вакансий и шаблонов.

```text
Корневая папка (Root)
-> Папки проектов (Project folders)
-> Папки вакансий (Vacancy folders)
-> Шаблоны в формате DOCX/DOCM
```

### Пример структуры:

```text
Яндекс Лавка/
    Сборщик/
        Договор.docx
        Доп соглашение.docx
Самокат/
    Курьер/
        Договор.docx
```

При запуске приложение считывает эту структуру, строит внутренний каталог `TemplateCatalog` и кэширует его в `cache/catalog.json`. Сами файлы шаблонов кэшируются в `cache/templates/`, а их метаданные — в `cache/metadata/`.

## Локальный запуск и тестирование

### Требования:
- Python 3.10+
- Установленный LibreOffice (для конвертации в PDF)

### Установка зависимостей:
```bash
pip install -r requirements.txt
```
*На Windows для корректной работы с часовыми поясами может потребоваться установка библиотеки `tzdata` (устанавливается автоматически при развертывании).*

### Запуск тестов:
```bash
python -m pytest
```

## Деплой на Сервер

Приложение разворачивается на сервере как системная служба.

### Шаги для обновления кода на сервере:
1. Создайте архив локальной папки `src`:
   ```powershell
   tar -czf src.tar.gz src
   ```
2. Отправьте архив на сервер:
   ```powershell
   scp src.tar.gz user@your-server-ip:/path/to/project/
   ```
3. Подключитесь по SSH, распакуйте файлы и перезапустите службу:
   ```bash
   ssh user@your-server-ip "cd /path/to/project/ && tar -xzf src.tar.gz && rm src.tar.gz && systemctl restart contract_bot"
   ```
4. Удалите локальный архив `src.tar.gz`.
